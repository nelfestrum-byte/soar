# Граница секретов в рантайме контента

> Написана 2026-08-06 вместе с
> `2026-08-06-connector-code-agent-unlock-design.md`, **не реализована**.
> Тот трек навёл порядок в API-поверхности (кто какие ручки зовёт) и честно
> записал, что этого недостаточно. Здесь — то, чего недостаёт, чтобы
> «роль `agent` не получает credential» стало утверждением о системе, а не о
> наборе роутов.

## [S1] Problem

После трека 2026-08-06 роль `agent` не читает конфиг коннектора ни одной
ручкой, а `HIDDEN_FIELDS` нельзя сузить. При этом credential достаётся ей в
одну строку кода:

```python
from soar.connectors.elastic import prod

class Exfil(ManualWorkflow):
    def run(self, context):
        print(prod.api_key)   # или prod._instance.api_key
        return {}
```

`PUT /workflows/{name}/code` — `_ADMIN` (`orchestrator/api/workflows.py:279-282`),
`POST /jobs` — `_RW` (`orchestrator/api/jobs.py:14`), `GET /logs/{job_id}` —
`_RW` (`orchestrator/api/logs.py:13-26`). Все три доступны `agent`.

Три независимых механизма, каждый из которых достаточен сам по себе:

**(a) `ConnectorProxy` не является барьером для чтения атрибутов.**
`soar/connectors/_proxy.py:25-29`:

```python
def __getattr__(self, name: str) -> Any:
    attr = getattr(self._instance, name)
    if name.startswith("_") or not callable(attr):
        return attr
    return self._wrapped(name, attr)
```

Не-callable атрибут возвращается сырым — а credential именно такой
(`self.api_key = api_key`, генератор пишет это на каждое поле из
`securitySchemes`, `orchestrator/core/openapi_generator.py:97-98`). Имена с
`_` в начале тоже проходят насквозь, поэтому `_instance` отдаёт сам
`BaseConnector` — при том, что докстринг файла (`_proxy.py:1-6`) утверждает
«шим никогда не отдаёт `self._instance` напрямую». Утверждение неверно с
момента написания; `__init__` кладёт `_instance` через
`object.__setattr__`, так что до `__getattr__` дело даже не доходит.

**(b) Скоуп-конфиг лежит рядом с джобом в открытом виде.**
`build_scoped_config` (`orchestrator/core/subprocess_runner.py:69-162`)
сужает набор инстансов до тех, что воркфлоу импортирует, и это работает как
задумано — но `params` копируются как есть, каталог делается
world-readable, а путь к нему субпроцесс знает из `SOAR_CONFIG`. Воркфлоу
читает `open(os.environ["SOAR_CONFIG"])` и достаёт креды, не касаясь ни
прокси, ни коннектора. Скоупинг уменьшает радиус поражения между джобами —
конфиденциальностью от автора воркфлоу он не является и не заявлялся.

**(c) Логи джоба не редактируются.** `soar/logger.py` не имеет фильтра;
единственная редакция в проекте — `_MASK` в API коннекторов (YAML/diff) и
`safe_kwargs` в `_proxy.py:41` (только kwargs вызова). Всё, что воркфлоу
напечатал, доступно через `GET /logs/{job_id}` роли `agent`.

## [S2] Solution — три части, разной цены

### 1. `ConnectorProxy` перестаёт отдавать секреты и `_instance`

```python
def __getattr__(self, name: str) -> Any:
    if name.startswith("_"):
        raise AttributeError(
            f"{name} is private to the connector; the proxy exposes public methods only"
        )
    attr = getattr(self._instance, name)
    if name in getattr(type(self._instance), "HIDDEN_FIELDS", set()):
        raise AttributeError(f"{name} is a credential and is not readable from workflow code")
    if not callable(attr):
        return attr
    return self._wrapped(name, attr)
```

`_instance`/`_type_name` живут в `__dict__` и продолжают резолвиться до
`__getattr__` — их надо закрыть отдельно, переименовав в
`__instance`/`__type_name` (name mangling) либо перекрыв `__getattribute__`.
Второе дороже по производительности на каждый доступ; первое ломает
`_wrapped`/`__repr__` внутри самого файла — правка локальная.

Заодно исправить докстринг: он должен описывать то, что код делает.

**Цена:** контракт рантайма контента меняется. Воркфлоу, читающий
`conn.base_url` (не-секрет), продолжает работать; читающий `conn.password`
или `conn._instance` — падает с `AttributeError` на джобе. Нужен прогон
`soar-content-pack` и запись в `docs/agents/known-limitations.md`/системный
промпт о том, что публично у коннектора только методы и не-hidden поля.

### 2. Редакция секретов в логах джоба

Значения hidden-полей известны воркеру: он строит scoped-конфиг и знает
инстансы. `SubprocessRunner` может передать список секретных значений
редактирующему обработчику лога — подстановка `***` по точному совпадению
подстроки перед записью в файл лога.

**Ограничение, которое надо записать в спеке честно:** это ловит
`print(conn.api_key)` и случайный `logger.info(config)`, но не ловит
`print(base64.b64encode(key))` и любое иное преобразование. Против
случайной утечки работает, против целенаправленной — нет. Не описывать это
как защиту от враждебного контента.

### 3. Скоуп-конфиг без plaintext (самая дорогая, возможно не нужна)

Варианты: передавать креды через stdin/pipe вместо файла; держать их в
памяти оркестратора и отдавать по запросу через сокет; шифровать файл
ключом, живущим только в окружении процесса. Все три упираются в то, что
код коннектора внутри того же субпроцесса всё равно получает значение в
открытом виде — то есть закрывают только «прочитать чужой конфиг файлом», а
не «прочитать свой credential». Учитывая (1), выигрыш невелик.

**Рекомендация:** делать 1 и 2, по 3 принять остаточный риск явной записью,
как это сделано для P15 в `UPGRADE-v2.md`.

## [S3] Чего эта спека не обещает

Даже полностью реализованная, она не превращает роль `agent` в границу
безопасности против целенаправленного атакующего: контент исполняется как
Python в субпроцессе, а `docs/concepts/ENTITY-MODEL.md` (слой 3 изоляции)
уже фиксирует, что защита рассчитана на «неаккуратный/умеренно враждебный
контент, не на целенаправленного атакующего с нативным кодом». Настоящая
граница потребовала бы иной модели исполнения (отдельный хост/VM, брокер
доступа к внешним системам вместо кред в процессе) — это другой продукт,
не правка этого файла.

Цель здесь скромнее и достижима: убрать пути, по которым секрет утекает
**без намерения его утащить**, и привести докстринги/документацию в
соответствие с тем, что код действительно гарантирует.

## [S4] Testing Strategy

- `conn.<hidden_field>` и `conn._instance` из кода воркфлоу → `AttributeError`;
  `conn.<non_hidden_field>` и вызов публичного метода → работают как раньше.
- Прогон тестов `soar-content-pack` — ни один коннектор/воркфлоу не читает
  атрибуты, которые перестали быть доступны.
- Джоб, печатающий значение секрета, → в `GET /logs/{id}` вместо значения `***`.
- Регрессия: аудит-строка `SOAR_AUDIT_EVENT connector.call` по-прежнему
  редактирует kwargs и не ломается на новом `__getattr__`.

## [S5] Success Criteria

- [ ] Из кода воркфлоу нельзя получить значение поля, объявленного в
      `HIDDEN_FIELDS`, ни через атрибут, ни через `_instance`
- [ ] Докстринг `soar/connectors/_proxy.py` описывает фактическое поведение
- [ ] Секрет, напечатанный воркфлоу, не виден в `GET /logs/{id}`
- [ ] Known Limitations #9 переформулирован под то, что осталось верным
      после реализации (или закрыт, если не осталось ничего)
