## Находки и решения (см. спеку [S1]/[S2] за деталями)

1. **6 job-статусов на 4 цвета Stitch** — экспорт даёт только
   `primary`(циан)/`secondary`(лавандовый)/`tertiary`(янтарь)/`error`(
   коралл), без «success». Решение (выбрано пользователем): добавить
   `success` (единственный по-настоящему новый цвет, подобран в той же
   M3-логике «светлый тон поверх насыщенного контейнера») и переиспользовать
   нейтральную пару `on-surface-variant`/`outline-variant` для `cancelled`
   — итоговые 6 цветов различимы попарно (закреплено тестом).
2. **Danger-кнопка и badge `failed` делят один красный** — Stitch не
   развёл их, хотя промпт Части 4 просил обратное. Развели не хue, а
   насыщенностью: кнопка — `error`/`on-error` (яркий коралл), badge —
   `error-container`/`on-error-container` (глубокий бордовый).
3. **Google Fonts CDN несовместим с air-gap** — самохостинг через
   `@fontsource/inter@5.3.0`, `@fontsource/jetbrains-mono@5.3.0`,
   `@fontsource/material-symbols-outlined@5.3.1`. Ноль внешних
   `<link>`/`url()` на `fonts.googleapis.com` — проверено тестом и
   вручную `grep`.
4. **Material Symbols — лигатурный шрифт целиком** — заменены только
   иконки, уже присутствовавшие как unicode-глифы в разметке Части 3
   (`⚙`→`settings`, `⋮`→`more_vert`, `▾`/`▸`→`expand_more`/
   `chevron_right`); подписи кнопок (Save/Close/Edit/Delete/...)
   остались текстом, как и в макетах Stitch.

## Что сделано

**Шрифты/иконки** (`ui/src/styles/fonts.css`, новый файл) — три
`@import` из `@fontsource/*` + утилитарный класс
`.material-symbols-outlined` (лигатурный рендер по имени глифа, как в
официальной таблице стилей Google, но без внешнего запроса).
Подключён из `main.js` рядом с `tokens.css`.

**Токены** (`ui/src/styles/tokens.css`, полная замена значений) —
поверхности/текст/границы теперь тёмные M3-тона; добавлены
`--space-7/8` (48/64px), `--radius-sm/md/xl/full`, блок `--text-*`
(h1/h2/h3/body/body-sm/code/label-caps — размер/вес/line-height/
tracking) и `--font-sans`/`--font-mono` с реальными именами шрифтов
(было `monospace` без имени).

**Точечные применения токенов типографики** (сверх буквального текста
плана, тот же приём, что уже был в Части 3 для цветов):
- `#app` — `font-family: var(--font-sans)`, фон/цвет из токенов
  (раньше приложение никак не задавало базовый шрифт и не красило фон
  вне `.card`/`nav`/`pre`).
- Глобальный `pre` — `font-family: var(--font-mono)` (раньше рендерился
  моноширинным только за счёт браузерного дефолта для `<pre>`, без
  реального JetBrains Mono).
- 25 inline `font-family:monospace` по 10 файлам (IDs, хэши, код,
  сигнатуры) — переведены на `var(--font-mono)`, иначе самохостинг
  JetBrains Mono не имел бы эффекта нигде, кроме `<pre>`.
- `h2` (глобальный) — на `--text-h3` (16px/600/24 — точное совпадение
  с прежним хардкодом `font-size:16px`, просто через токен).
- `.badge` — `border-radius` на `--radius-xl` (12px, «pill» по
  `DESIGN.md`: «Small, pill-shaped (rounded-xl)»), было `10px` литералом.
- `ui/index.html` — предзагрузочный inline `<style>` (фон/цвет до
  монтирования Vue) — с `#f5f5f5`/`#333` на `#0b1326`/`#dae2fd`, иначе
  при первой отрисовке был бы светлый «мелькающий» кадр перед тёмной
  темой.

**Иконки в разметке** — `App.vue` (nav more-toggle), `RowMenu.vue`
(⋮-toggle), `Workflows.vue` (detail-toggle chevron).

## Вес бандла

Новые статические ассеты в `dist/assets/`: **≈1.5 МБ** суммарно
(`du -ch dist/assets/*.woff2 dist/assets/*.woff`). Основной вклад —
Material Symbols Outlined (320 КБ woff2 + 376 КБ woff = ~700 КБ,
лигатурный шрифт на весь набор глифов, не подмножество на 15-20
иконок, см. спеку [S5]). Inter/JetBrains Mono — несколько subset-файлов
на каждое начертание (latin/cyrillic/greek/vietnamese и т.д.,
генерируются пакетом автоматически); реально скачивается браузером
только тот subset, чей `unicode-range` совпадает с текстом на
странице (кириллица нужна — в UI русские строки; греческий/
вьетнамский — балласт в образе, не в рантайм-трафике конкретного
пользователя). Итоговый прирост веса Docker-образа — не измерялся
отдельно в этом отчёте, но ~1.5 МБ statических файлов пренебрежимо
малы на фоне уже существующих зависимостей `ui/node_modules`.

## Известные ограничения

- **Светлой темы нет** — Stitch отдал только тёмный вариант, несмотря
  на то что промпт Части 4 просил оба. Зафиксировано в спеке [S3] как
  ограничение, не блокирует внедрение тёмной.
- **Ручная визуальная проверка в браузере не выполнена** — та же
  причина, что и в отчёте по Части 3 (нет headless-браузера в этом
  окружении). Проверено: `npm run dev` отдаёт 200 и не падает,
  `npm run build` собирается чисто, юнит-тесты бьют по факту наличия
  иконок/токенов в DOM.
