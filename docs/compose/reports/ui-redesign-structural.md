## Что сделано

**Стадия A — `tokens.css`.** Новый `ui/src/styles/tokens.css`,
импортируется из `main.js` перед `mount()`. Инвентаризация дала 29
уникальных hex-цветов в 16 файлах — все стали переменными:
поверхности, текст (3 яруса), границы, акцент/danger/success, 6 пар
статус-бейджей, spacing-шкала 4–32px, radius, `--font-mono`. Одно
сознательное упрощение: разрозненные оттенки серого для приглушённого
текста (`#555/#666/#888/#999/#aaa/#ccc`) схлопнуты в два токена
(`--color-text-muted`, `--color-text-faint`) — визуально неразличимо,
но убирает бессистемный разброс. `App.vue` и все 16 файлов переведены
на `var(--...)`; тест `tokens.spec.js` проверяет полноту набора токенов
и **регрессионно** — отсутствие hex-литералов вне `tokens.css`.

**Стадия B — nav-группировка.** `App.vue`: Status/Workflows/Jobs/
Actions/Connectors — всегда видимые ссылки; Tools/Prompts/Generate/
Settings/Users/API Keys/Audit Log — под toggle `⚙ More`
(`v-show`, не `v-if`, — секция остаётся в DOM, поэтому старый
`nav.spec.js` с проверкой `.text()` не потребовал переписывания).
Состояние open/closed — `localStorage['soar.nav.moreOpen']`, читается
при монтировании, закрытие по клику вне.

**Стадия C — `RowMenu.vue`.** Новый компонент: toggle «⋮» + слот-панель,
закрытие по клику на пункт и по клику вне. Применён в трёх вьюхах:
Workflows (видима только Edit/View; Enable/Disable, Run, Jobs, Audit,
Delete — в меню), Connectors (видимы Edit и Setup — оба одинаково
частые; Audit/Delete — в меню), Actions (Audit/Delete — в меню, ради
единообразия паттерна, хотя пунктов всего два). `Jobs.vue` не тронут —
там и так не больше 3 действий в строке.

**Стадия D — toolbar редактора.** В Workflows/Actions/Connectors
(код и конфиг) строка вкладок+Save/Close вынесена в `.editor-toolbar`
(`position: sticky; top: 0`) под отдельным `<h2>` — раньше была одним
flex-рядом с заголовком.

**Стадия E — `Loading.vue` + `.empty`.** Новый компонент со спиннером
(`--color-accent` акцент, CSS-анимация без библиотек) заменяет
`<div class="loading">Loading...</div>` во всех 13 вьюхах, где встречался
паттерн. Класс `.loading` (ранее одновременно и «идёт загрузка», и
«список пуст» — например, `Actions.vue` использовал его для «No actions
yet») разведён: `.empty` — для отсутствия данных (14 мест), `.loading`
в `App.vue` удалён как мёртвый CSS (теперь `.loading-spinner` живёт
scoped в `Loading.vue`).

## Тесты

73 теста (было 60), новые файлы: `tokens.spec.js` (2),
`row-menu.spec.js` (4), `editor-toolbar.spec.js` (3), `loading.spec.js`
(2); `nav.spec.js` расширен на 4 теста коллапс-группы.

Находка по ходу работы: `@vue/test-utils.mount()` без `attachTo` не
крепит элементы к `document`, а `getComputedStyle` в jsdom для
отсоединённых узлов не пересчитывается корректно **после повторного**
обновления стиля (первый рендер — верно, второй — возвращает
UA-дефолты). Из-за этого `isVisible()`/`getComputedStyle`-тесты на
`v-show`-переключение (nav more-panel) давали ложный результат при
повторном клике. Починено через `attachTo: document.body` +
`unmount()` в `afterEach`. Пригодится в любых будущих тестах, где
видимость проверяется больше одного раза за тест.

## Ручная проверка

`npm run build` — чистая сборка, 63 модуля, без ошибок.
`npm run dev` — сервер поднимается, `index.html`/JS/CSS бандл отдаются
(200), без ошибок компиляции.

**Не выполнено**: интерактивная проверка в браузере (клик по nav
`More`, открытие `RowMenu`, скролл с sticky-toolbar) — нет headless
браузера в этом окружении (Windows, `chromium-cli`/Playwright не
установлены), а для настоящих authenticated-данных нужен поднятый
оркестратор+Redis, что непропорционально объёму структурной правки.
Вместо этого поведение проверено юнит-тестами, которые буквально
кликают по DOM и проверяют видимость/классы (`row-menu.spec.js`,
расширение `nav.spec.js`) — то же самое, что глазами увидел бы человек,
без снятия скриншота.
